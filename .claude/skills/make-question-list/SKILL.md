# 문항목록 만들기

## 1. 언제 쓰는지
- `원문/`의 자료요구서 PDF를 문항별로 나누고, 프로젝트 루트의 `split.py`가 검토된 `data/문항목록.csv`와 같은 결과를 내야 할 때 쓴다.
- 작업 전에 `PROGRESS.md`, `CONTEXT.md`, `처리지침.md` 제2장, 현재 `split.py`, PDF 원문과 검토된 CSV를 읽는다. 검토된 CSV가 없으면 원문과 사용자가 지정한 출력 형식을 기준으로 삼는다.

## 2. 순서
1. 프로젝트 `.venv`에서 `pypdf` 설치 여부를 확인한다. 없으면 `pip install pypdf`를 제시하고 사용자 허락을 받은 뒤 설치한다.
2. PDF에서 위원회·의원·제출기한을 읽고, 줄 맨 앞의 `숫자.`로 새 문항을 시작한다. `가.`·`나.` 등은 같은 문항의 세부항목, `※`는 비고다. 그 밖의 줄은 직전 항목에 잇는다. `수신:`, `담당 보좌관:`, `끝.`은 문항에서 제외하고 이름·연락처를 저장하지 않는다.
3. `split.py`가 없으면 프로젝트 루트에 만들고, 있으면 필요한 부분만 고친다. `pypdf`와 Python 표준 라이브러리만 사용한다. 결과 열은 `파일명, 위원회, 의원, 제출기한, 문항번호, 요구내용, 세부항목, 비고` 순서로 하고 UTF-8-SIG CSV를 만든다.
4. 이 프로젝트에서 검토된 CSV 표기를 따른다. 세부항목 여러 개는 원래의 `가.`·`나.`를 보존한 채 ` / `로 잇고, 비고에는 원문의 `※`만 빼고 문구를 담는다. 제출기한은 `YYYY-MM-DD`로 쓴다.
5. 기존 `data/문항목록.csv`는 검토 기준으로 보존한다. `split.py`의 추출 결과를 메모리나 별도 임시 위치에서 실행해 검토된 CSV와 모든 열·행을 비교한다. 새 CSV를 써야 할 때에는 사용자가 지정한 출력 위치를 확인하고 기존 파일을 덮어쓰지 않는다.

## 3. 끝나는 조건
- 파일별 문항 수가 파일명에 적힌 수와 같고, 문항번호가 1부터 마지막까지 연속이다.
- 검토된 CSV가 있으면 모든 행과 열이 같고, 세부항목·비고가 함께 있는 문항을 각 PDF 원문과 대조했다.
- CSV에 보좌관 이름·연락처가 없고, 원문 PDF 및 기존 `data/` 파일이 바뀌지 않았다.

## 4. 하지 말 것
- 원문 PDF, 과거 접수대장, 교체된 문항목록 CSV를 검증 없이 수정하거나 덮어쓰지 않는다.
- 원문에 없는 문항·날짜·내용을 보태지 않는다. 문항 경계가 불명확하거나 수가 맞지 않으면 원문을 재확인하고 해결되지 않은 부분을 보고한다.
- 답변 작성, 배분 확정, 결재·제출 기능을 추가하지 않는다.
